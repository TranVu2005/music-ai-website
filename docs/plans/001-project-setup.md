## 3. Prisma Wiring

- **Configuration location**: `package.json` config property `"prisma": { "schema": "src/db/schema.prisma" }`.
- **Reason & Deprecation Note**: Canonical mechanism supported natively by Prisma 6.x CLI without needing ad-hoc flags or extra configuration files. Prisma 6.x emits a deprecation warning indicating `package.json#prisma` will be removed in Prisma 7 in favor of `prisma.config.ts`. This warning is expected and documented in `README.md` under "Database" alongside the Prisma 7 migration path.
- **Dockerfile alignment**:
  - `Dockerfile` Stage 2 executes `COPY src/db ./src/db/` prior to `npm ci`.
  - `Dockerfile` Stage 3 executes `RUN npx prisma generate`, discovering `src/db/schema.prisma` via `package.json` and generating `@prisma/client` into `node_modules/.prisma`.
  - `Dockerfile` Stage 4 copies both query engine and schema into the runner image:
    ```dockerfile
    COPY --from=builder --chown=nextjs:nodejs /app/node_modules/.prisma ./node_modules/.prisma
    COPY --from=builder --chown=nextjs:nodejs /app/src/db ./src/db
    ```
- **Direct URL**: Configured in `src/db/schema.prisma` under `datasource db` via `directUrl = env("DIRECT_URL")` alongside `url = env("DATABASE_URL")`. Documented in `README.md` under "Database".

## 4. CI (`.github/workflows/ci.yml`)

### Job 1: `checks`
- **Runner**: `ubuntu-latest`
- **Service**:
  - `postgres:16-alpine` container on port `5432:5432`
  - Health check: `pg_isready -U postgres -d music_shop_db`
  - Service env: `POSTGRES_USER: postgres`, `POSTGRES_PASSWORD: postgres`, `POSTGRES_DB: music_shop_db`
- **Job Env**:
  - `DATABASE_URL: "postgresql://postgres:postgres@localhost:5432/music_shop_db?schema=public"`
  - `DIRECT_URL: "postgresql://postgres:postgres@localhost:5432/music_shop_db?schema=public"`
- **Step sequence**:
  1. `Checkout repository` (`actions/checkout@v4`)
  2. `Setup Node.js` (`actions/setup-node@v4` with `node-version: 20`, `cache: 'npm'`)
  3. `Install dependencies` (`run: npm ci`)
  4. `Check audio file guard` (`run: npm run check:audio`)
  5. `Run linter` (`run: npm run lint`)
  6. `Type check` (`run: npm run typecheck`)
  7. `Generate Prisma client` (`run: npm run prisma:generate`)
  8. `Run unit & integration tests` (`run: npm run test`)
  9. `Deploy DB migrations (validate DIRECT_URL)` (`run: npm run db:migrate:deploy`)
  10. `Build application` (`run: npm run build`)

### Job 2: `docker`
- **Runner**: `ubuntu-latest`
- **Step sequence**:
  1. `Checkout repository` (`actions/checkout@v4`)
  2. `Build Docker image` (`run: docker build -f build/deploy/Dockerfile -t music-shop:ci .`)
  3. `Start Docker container` (`run: docker run -d -p 3000:3000 --name music-shop-app music-shop:ci`)
  4. `Poll health check` (`run: for i in $(seq 1 30); do curl -fsS http://localhost:3000/api/health && exit 0; echo "Waiting ($i/30)..."; sleep 1; done; docker logs music-shop-app; exit 1`)

## 6. Risks / Open Questions

1. **Docker Desktop Local Availability**: Docker Desktop daemon must be active locally to execute the local container verification commands.
2. **Line Endings & Executable Bit**: On Windows host, `.gitattributes` enforces LF line endings for shell scripts and hooks (`*.sh text eol=lf`, `.githooks/* text eol=lf`), and `git update-index --chmod=+x` sets mode `100755` for `tools/check-audio.sh` and `.githooks/pre-commit`.
3. **TypeScript clean typecheck**: `next-env.d.ts` is gitignored; `typecheck` script is configured so that `npm run typecheck` succeeds on clean checkout without a prior build (running `next typegen && tsc --noEmit` if necessary).
4. **Dynamic Health Route**: `src/app/api/health/route.ts` specifies `export const dynamic = "force-dynamic";` ensuring it is never statically pre-rendered at build time.
5. **Zero-Migration Verification**: `prisma migrate deploy` creates the `_prisma_migrations` tracking table against `DIRECT_URL` and exits cleanly with 0 pending migrations.
